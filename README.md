# Workplot

Workplot은 반복할 업무를 와이어로 설계하고 로컬 Codex로 실행하는 작업실입니다. 예를 들어 화면 개선 흐름을 한 번 만들어 두면, 매 회차 다른 불편을 골라 수정하고 전후 화면을 비교한 뒤 다음 과제를 인계할 수 있습니다. [제품 요구사항(PRD)](https://chatgpt.com/space/page_61bc38060bb88191b00f1fdf8fd6edaf)

## 첫 워크플롯 실행하기

1. **흐름 설계**에서 노드를 선택해 역할과 지침을 읽고, 연결선을 따라 자료를 받을 다음 단계와 승인 위치를 확인합니다. 지침을 수정해 저장하면 새 버전이 생깁니다. 진행 중인 실행은 시작할 때 선택한 버전을 따릅니다.
2. **내 워크플로**에서 저장한 흐름을 열고 **이번 작업 요청**에 이번 회차에서 할 일을 적습니다. 파일·폴더는 참고 자료로 첨부하고, 소스를 고칠 때는 수정할 작업 폴더를 따로 지정합니다. 화면 개선 흐름에서 요청을 비우면 현재 화면과 최근 세션 결과를 보고 과제를 고릅니다.
3. **실행 현황**에서 현재 단계와 대기 사유를 확인합니다. 결과 문서를 열면 그 회차의 산출물을 읽을 수 있습니다. 흐름 설계에서도 노드의 결과 파일명을 눌러 회차를 고르고 직전 결과와 나란히 비교할 수 있습니다.
4. 다음 회차까지 맡기려면 **자동승인 설정**에서 종료 시각과 추가 회차 범위를 정합니다. 목표를 설정한 경우에는 합격 기준도 확인합니다. 추천 과제를 직접 승인하는 흐름에서는 중간 검토가 돌아올 때 사용자가 결정합니다. 마지막 승인을 위임하면 인계한 과제로 다음 회차를 시작합니다. 종료된 루프는 완료 화면의 **마지막 인계로 새 실행**에서 이어갈 수 있습니다.

## 병렬 개발과 결과 확인

같은 저장소에서 여러 과제를 진행하려면 **개발 작업 실행** 옆에서 남은 슬롯을 확인하세요. CPU와 메모리에 따른 추천 한도를 확인하고 실행 한도를 조절할 수 있습니다. 각 개발 작업은 별도 Git worktree와 작업 브랜치에서 진행됩니다.

검증 후 Git 커밋 노드를 둔 흐름은 실제 변경과 검사 결과를 확인해 작업 브랜치에 커밋하거나 생략 이유를 기록합니다. 원본에 반영할 때는 통합 큐에서 검사를 통과한 후보 SHA와 변경 내용을 확인하고 승인합니다. 검증 뒤 원본 브랜치가 바뀌면 재검사가 필요합니다. [Git 개발·통합 절차](docs/git-development-plan.md) · [병렬 개발 계획](docs/parallel-development-plan.md)

실행 현황 대시보드에서 진행 과제, 회차별 결과와 사용자 판단이 필요한 작업을 확인할 수 있습니다. 같은 로컬 서버에 접근할 수 있는 Codex 대화에서 `$workplot 워크플롯 현황 알려줘`라고 요청하면 실행 기록을 바탕으로 요약 리포트를 받을 수 있습니다.

기본 스킬 이름은 `workplot`입니다. 로컬 서버는 새 흐름이나 와이어 변경안을 설계할 때 이 스킬의 지침을 Codex에 전달합니다. [스킬 원본](.agents/skills/workplot/SKILL.md)

## 대시보드와 와이어 편집

첫 화면은 실행 현황입니다. 왼쪽 **흐름 설계**에서 예시를 편집하거나 **흐름 목록**에서 저장한 흐름을 엽니다. 저장한 버전을 실행하면 해당 실행의 문서·승인·중단 화면으로 이동합니다. 검토 대기 건은 현황에서 **검토 열기 → 검토할 문서 열기**로 들어갑니다. 오른쪽 패널에서 고정 버전의 단계와 최근 실행 로그를 확인할 수 있습니다. 편집기에서는 오른쪽 출력 단자를 다음 단계의 왼쪽 입력 단자로 연결합니다. 키보드로는 ‘다음 단계 연결’을 사용합니다. 연결을 바꾸면 업무 설계서가 갱신되며 모든 단계를 한 줄로 연결한 뒤 새 버전을 저장할 수 있습니다. 실행 중인 버전은 시작 시점의 흐름을 따릅니다.

**목표로 시작 → 흐름 찾기**에서 원하는 문서를 입력하면 Codex가 내 워크플로의 이름·목표·단계·입력 항목을 살펴봅니다. 맞는 흐름이 있으면 하나와 그 이유를 보여줍니다. **이 흐름 사용**을 선택하면 추천한 버전으로 새 자료를 입력할 수 있습니다. 맞는 흐름이 없거나 **새 흐름 설계**를 선택하면 설계안을 만듭니다.

와이어 편집기 하단 **말로 흐름 수정**에서 `$`를 입력하면 현재 프로젝트에서 로컬 Codex가 활성화한 개인·프로젝트·플러그인·기본 스킬을 검색할 수 있습니다. 방향키와 Enter로 고르고 이름을 눌러 선택한 스킬의 실제 `SKILL.md`를 읽을 수 있습니다. 요청을 보내면 Codex가 변경안을 제안하고, **변경안 적용**을 누르면 편집기에 반영됩니다. 특정 작업에 스킬을 연결해 달라고 하면 와이어에 실행 스킬이 표시됩니다. 적용·저장한 뒤에는 해당 작업에서만 저장 당시와 일치하는 `SKILL.md` 지침을 Codex에 전달합니다. 적용 대상이 모호하면 먼저 질문합니다.

**내 워크플로 → Codex 스킬로 등록**에서 개인 스킬 이름을 정하면 `~/.agents/skills/<이름>/SKILL.md`가 생성됩니다. 로컬 Workplot 서버가 켜진 상태에서 새 Codex 대화에 `$shop-intro 이 자료로 실행해줘`처럼 요청하세요. 등록한 버전으로 실행되며 승인·질문·결과는 실행 링크에서 확인합니다. 흐름을 수정한 뒤에는 **등록한 스킬 관리 → 업데이트**로 실행 버전을 바꿀 수 있습니다.

**내 워크플로 → 예약 추가**에서 버전을 고정하고 매일 또는 매주 실행할 서울 시각을 정합니다. 등록한 고정 자료 또는 `.local/schedule-inputs/` 안의 지정한 텍스트 파일 한 개를 사용합니다. 파일은 매 회차 새로 읽습니다. 로컬 서버가 꺼져 있거나 Mac이 잠든 동안 놓친 회차는 소급 실행하지 않습니다. 작업 중·승인 대기와 겹치면 건너뛰며, 최근 예약 결과는 보관함에서 확인합니다. Codex에서 `$workplot shop-intro 예약 보여줘`처럼 요청해 조회·등록·변경·일시정지·재개·삭제할 수도 있습니다.

## 실행

이 Mac에서는 새 Codex 대화에서 `$workplot`을 입력하면 로컬 서버의 상태를 확인하고 필요할 때 시작한 뒤 대시보드 링크를 제공합니다. 개인 스킬 `~/.agents/skills/workplot`은 이 프로젝트의 `.agents/skills/workplot`에 연결돼 있습니다. 포트는 4310이며, 스킬이 시작한 서버의 로그는 `.local/dashboard-server.log`에 남습니다.

Node.js 26.13.1과 함께 제공되는 npm을 사용합니다. 기존 nvm에 설치한 후 이 폴더에서 실행하세요.

```sh
nvm use
npm ci
npm run dev
```

개발 화면: <http://127.0.0.1:5173>, 로컬 API: <http://127.0.0.1:4310/api/health>.
종료는 Ctrl+C입니다. 이미 실행 중인 서버가 있으면 해당 서버를 먼저 종료해야 합니다.

빌드한 화면과 API를 하나의 로컬 서버에서 실행하려면:

```sh
npm run build
npm start
```

이때 화면 주소는 <http://127.0.0.1:4310>입니다. 서버는 루프백 주소에서만 수신합니다.
SQLite는 저장소의 `.local/studio.sqlite`에 생성되며 Git에 포함되지 않습니다.
`/api/tools`는 서버의 PATH에서 고정된 `claude --version`, `codex --version`을 실행하고 서버 수명 동안 결과를 공유합니다. 새로 설치한 도구를 다시 감지하려면 서버를 재시작하세요. 실행할 때만 공식 Codex의 ChatGPT 로그인 상태를 확인합니다. 같은 실행 터미널의 PATH에서 `codex`가 확인되어야 합니다. 브라우저와 로컬 서버 사이의 저장 계약과 세션 검사는 [T02 작업 정의와 실행 기록 저장](apps/server/T02.md)에 정리했습니다.

## 구성

- `apps/web`: React 19, Vite 8, React Flow, CSS Modules
- `apps/server`: Fastify 5, SQLite/better-sqlite3, 기존 Codex CLI 연결과 작업 버전·실행 저장
- `packages/contracts`: Zod 공통 저장·응답 계약
- `e2e`: Playwright 브라우저 검사

공통 패키지를 먼저 빌드하도록 루트 명령에 순서가 설정되어 있습니다. `npm run dev`는 세 작업 공간의 변경을 감시합니다.
Node 버전은 `.nvmrc`, `.node-version`, `engines`에, 패키지 설치 결과는 `package-lock.json`에 고정합니다.

실행이 실패하면 대시보드에서 **실패 상세 열기 → 실패한 단계 다시 실행**을 누르세요. 같은 실행 ID와 워크플로 버전에서 해당 작업을 다시 시작합니다. 승인한 문서가 바뀌면 재실행이 차단됩니다. 재실행 정보가 저장되기 전에 만들어진 실패 기록은 조회할 수 있습니다.

## 검증

편집·실행·승인·중단을 한꺼번에 검증하려면 `npm run qa`를 실행하세요. 격리된 로컬 서버에서 브라우저 회귀 검사와 실제 Codex 검사를 순차 실행합니다. [QA 항목과 실행 조건](docs/phase-1/qa.md)

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
```

앱의 모델 API 직접 호출·API 키 설정·SDK 기반 실행을 사용하지 않습니다. 사용자가 선택한 기존 Claude Code·Codex 도구를 연결하는 방향입니다. [AGENTS.md](AGENTS.md)의 규칙을 따릅니다. 기존 API 연결 계획은 중단했고 실제 호출 경로를 제거했습니다.

[T01 로컬 검증](apps/server/T01.md)의 준비 명령은 외부 호출 없이 실행됩니다. `--live`는 차단됩니다. API 키·모델·예산 설정을 요구하지 않습니다. 기존 도구의 로그인은 공식 도구에서 처리하며, 내부 서비스 통신과 계정 사용 한도는 해당 도구에 따릅니다.
