# Workplot

## 작업실 열기

사용자가 `$workplot`만 입력하거나 Workplot 실행을 요청하면 현재 폴더에서 다음 명령을 실행한다. 실행기는 서버가 준비되면 대시보드 주소를 출력한다. 그 주소를 클릭 가능한 링크로 전달한다. 브라우저까지 열어 달라는 요청이 있으면 해당 주소를 연다. 샌드박스가 로컬 연결이나 서버 시작을 차단하면 이 명령에 필요한 권한을 요청한다. 서버 시작은 문서 작업을 시작하거나 승인하지 않는다.

```sh
python3 "$HOME/.agents/skills/workplot/scripts/open_dashboard.py"
```

## 예약 관리

사용자가 Workplot에서 등록한 스킬의 예약을 요청하면 작업실의 로컬 예약을 관리한다. 예약 요청으로 해당 문서 업무를 즉시 실행하지 않는다. 대상 흐름, 반복 시각, 자료 방식이 불명확하면 필요한 값만 묻는다. Mac이 깨어 있고 로컬 서버가 실행 중이어야 한다. 시간대는 서울이다.

다음 명령의 동작은 `show`(조회), `create`(추가), `update`(변경), `pause`, `resume`, `delete`이다. 예를 들어 `$shop-intro`의 예약을 조회하려면 다음을 실행한다.

```sh
python3 -B "$HOME/.agents/skills/workplot/scripts/manage_schedule.py" show shop-intro
```

추가와 변경은 표준입력으로 JSON을 전달한다. 예를 들어 매주 월요일 오전 9시에 지정 파일을 읽는 설정은 `{"weekday":1,"time":"09:00","material":{"kind":"file","value":"주간자료.md"}}`이다. 매일은 weekday=null, 일요일은 0이다. 고정 원문은 `{"kind":"text","value":"사용자가 준 원문"}`으로 전달한다. 파일은 조회 결과의 자료 폴더 안에 있어야 한다. 변경 시 요청한 항목만 보내면 다른 설정과 고정 버전은 유지된다. 서버 응답에서 저장 결과와 다음 회차를 확인한다.

## 흐름 설계 및 수정

Workplot이 설계안을 요청하거나 사용자가 와이어 변경을 요청한 경우 다음 지침을 적용한다.

사용자가 원하는 결과와 화면에서 선택한 작업 방식을 함께 읽고 설계안을 제안한다. 설계안을 적용·저장하거나 업무를 실행하는 시점은 사용자가 결정한다.

- 필요한 문서가 불분명하면 어떤 결과물을 원하는지 한 가지 질문을 한다. 주소나 영업시간처럼 실행 전에 제공할 자료는 그때 입력받는다.
- 단일 문서는 작업 하나로 시작한다. 사용자가 승인 후 비교를 선택했다면 초안 작성 → 사용자 승인 → 수정안 작성으로 연결하고, 수정 단계에 승인된 초안을 전달한다.
- 기존 와이어를 수정할 때는 요청이 영향을 주는 단계와 입력 연결을 바꾼다. 예를 들어 AI 검토를 추가하면 기존 사용자 승인 단계를 보존하고, 수정본에 초안과 검토 의견이 모두 필요할 때는 두 작업의 문서를 입력으로 지정한다.
- 현재 지원 범위는 로컬 문서 작성·검토와 사용자 승인이다. Slack 발송처럼 외부 행동이 포함되면 해당 서비스로 직접 발송하는 기능이 없음을 한국어로 알리고, 발송용 문서 작성까지만 진행할지 먼저 묻는다. 동의하면 문서 작성 단계만 제안한다.

## 자주 쓰는 변경 요청

사용자가 고른 한 문장에 집중한다. 목적이 이미 충족되면 별개의 개선을 끼워 넣지 않는다. 검토를 강화할 때는 기존 작업에서 무엇을 원본과 대조할지 구체화하고, 목표를 나눌 때는 각 세부 목표와 확인 가능한 완료 기준을 연결한다. 선택지를 요청하면 기존 작성 작업의 지침에서 장단점을 담은 question을 반환하고 사용자 답을 기다린 다음, 같은 작업에서 선택한 안으로 document를 작성하게 한다. 사용자 승인 노드는 승인 또는 거절만 받으므로 번호나 의견을 입력받을 수 없다. 선택만을 위해 승인 노드나 후속 단계를 추가하지 않는다. 사람이 초안을 확인한 뒤 수정하겠다는 요청은 두 작업 사이의 사용자 승인 노드로 표현한다. 이때 기존 작업 지침과 문서 연결은 보존한다.
