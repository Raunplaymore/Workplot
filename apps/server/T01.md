# T01 기존 에이전트 도구 연결 계획

사용자가 이미 쓰는 Claude Code·Codex를 브라우저 작업실에 연결한다. 앱이 모델 API를 직접 호출하거나 API 키·별도 모델 과금 설정을 요구하지 않는다. 기존 도구의 공식 로그인·권한 처리를 이용한다. CLI 연결은 사용자가 선택한 방향이며 API 우회를 위해 숨긴 키·프록시·SDK를 추가하는 것은 금지한다.

## 구조와 경계

브라우저 → Fastify 로컬 서버 → 앱이 시작한 기존 CLI 프로세스 → 로그·결과 파일 → 로컬 서버 → 브라우저로 연결한다. 로컬 HTTP·SSE는 화면과 서버 사이의 내부 통신이며 모델 API 직접 호출과 구분한다. 도구 자체는 외부 서비스와 통신할 수 있으므로 완전 오프라인·무제한·추가 비용 없음으로 표현하지 않는다.

Node child_process로 도구 하나부터 연결한다. shell 문자열 합성 대신 고정 실행 파일과 인자 배열을 사용한다. 사용자 기존 세션을 임의로 붙잡거나 종료하지 않는다. 도구의 출력이 구조화돼도 질문·승인을 모두 제어할 수 있다고 가정하지 않는다.

## 확인한 것과 남은 것

2026-11-16 로컬 `--version`과 `--help` 확인: Codex CLI 0.166.0, Claude Code 2.1.293이 설치돼 있다. Codex exec에는 JSONL 이벤트·최종 출력 파일·JSON Schema 옵션이, Claude Code에는 print·stream-json·JSON Schema 옵션이 표시된다. 이는 인터페이스 존재 확인이며 로그인·계정 종류·실제 동작 검증은 아니다. 인증 파일·토큰은 읽지 않았다.

## 연결 순서와 통과 기준

| 단계        | 수행할 검증                                         | 통과 기준                                                                       |
| ----------- | --------------------------------------------------- | ------------------------------------------------------------------------------- |
| 1 도구 확인 | 설치 버전·공식 로그인 상태 확인 경로·실행 방식 점검 | 앱이 키·토큰을 읽거나 API 방식으로 바꾸지 않고 기존 도구 사용 가능 여부를 표시  |
| 2 단일 작업 | 별도 작업 폴더에서 가상 자료로 문서 생성            | 실행 ID·소유 프로세스·종료 코드·결과 파일을 연결하고 파일을 다시 열 수 있음     |
| 3 상태 관제 | 실제 구조화된 출력과 파일 기록 수집                 | 실행·대기·실패·완료를 근거로 표시, 형식 불명 출력은 추측하지 않음               |
| 4 결과 검토 | 문서 생성 후 사용자 승인 대기                       | 승인 전 다음 업무 단계 호출 0회, 거절 후 후속 실행 0회                          |
| 5 도구 권한 | CLI 내부의 권한 요청·거절·허용을 따로 검증          | 실제 위험 행동이 승인 전 차단됨. 업무 단계 승인과 CLI 도구 승인을 혼동하지 않음 |
| 6 중단      | 앱이 시작한 프로세스만 중단하고 종료 확인           | 새 작업 호출 0회, 종료 미확인은 상태 불명. 타 사용자 세션에 영향 없음           |
| 7 결과 전달 | 결과 파일을 다음 새 작업에 입력으로 전달            | 파일 해시와 다음 입력 해시 일치, 이전 결과 보존                                 |
| 8 장애      | 로그인 만료·사용 한도·출력 형식 변경·프로세스 종료  | API fallback 없이 원인과 복구 방법 표시, 자동 중복 실행 금지                    |

두 도구를 동시에 완성하지 않는다. 설치·계정 사용 방식·승인·중단 제어를 확인한 뒤 첫 연결 도구 하나를 선정한다. 비대화형 CLI가 도구 승인을 전달하지 못하면 권한을 우회하지 않는다. 해당 기능을 미지원으로 표시하고 공식 도구에서 사용자 직접 처리 후 상태를 재확인하는 경로를 검토한다. 브라우저 안에서만 모든 일을 완료한다는 목표는 이 제약 해소 후 판정한다. 내장 터미널은 필요가 입증될 때 범위를 재검토하며 이번 변경으로 자동 도입하지 않는다.

## 과제 변경

T01은 기존 도구 연결 가능성 검증, T02는 실행 ID·CLI 종류/버전·프로세스 소유권·로그 위치·결과 참조 저장, T03은 직렬 프로세스 실행과 업무 승인·CLI 권한의 구분을 담당한다. T04는 지원 능력에 맞는 담당자·스킬 편집, T05는 같은 CLI로 흐름 초안을 받아 Zod 검증, T06은 실제 출력 기반 픽셀 표시, T07은 파일 전달·부분 재실행, T08은 프로세스·로그 복구, T09는 CLI 실행 조건을 기록한 수정안 비교, T10은 기존 도구 연결·로그인·시작 경험을 검증한다.

자연어 설계·평가도 별도 모델 API를 추가하지 않는다. CLI에서 해당 구조화된 작업이 검증되기 전에는 직접 편집·규칙 검사만 제공하고 생성 기능을 구현된 것처럼 표시하지 않는다.

## 앱의 설치 감지 구현

T01 첫 단계인 설치 감지와 작업실 표시를 구현했다. 고정된 --version 명령만 실행하고 실행 시간 5초·출력 8KiB 제한, shell 비사용, 서버 수명별 감지 공유를 적용한다. 발견·미발견·확인 실패를 구분하고 원시 오류나 출력은 브라우저에 반환하지 않는다. 이 앱 화면은 설치 감지 범위다. CLI 실제 검증은 아래에 기록했다. 과거 API probe의 실제 호출 경로는 제거된 상태를 유지하며 `--live`는 차단된다. 과거 Claude Agent SDK 의존성과 실제 실행 경로와 무관했던 SDK 시험 코드를 제거했다. T01 실제 CLI 증거와 비활성화된 probe 검사는 유지한다.

## 첫 구현 검증 기록

2026-11-16, macOS arm64, Node 26.13.1, 아직 커밋 없는 작업 상태. 타입·lint·형식·빌드, Vitest 12개, Chromium Playwright 3개가 통과했다. 실제 detectTools 실행에서 Claude Code 2.1.293과 Codex 0.166.0을 감지했다. 로그인은 unchecked로 유지한다.

검증 코드는 apps/server/test/tools.test.ts와 e2e/studio.spec.ts다. 정상 버전, 미설치와 실행 오류 구분, 알 수 없는 출력 비노출, 동시 요청의 단일 감지, 부분 설치 상태의 화면 표시와 실행 버튼 비활성화를 검사했다. 이 결과는 T01 전체 완료나 실제 에이전트 실행 성공을 뜻하지 않는다.

## 실제 Codex 연결 검증

2026-11-17, macOS arm64, Node 26.13.1, Codex CLI 0.166.0. 공식 `codex login status`는 ChatGPT 로그인을 보고했고, `codex app-server --stdio`의 `account/read`에서도 `chatgpt`를 확인했다. Claude Code 2.1.293은 공식 상태 확인에서 로그인되지 않았다. **T02와 T03의 첫 제공자는 Codex로 선정한다.**

Node가 고정된 인자 배열로 새 Codex 프로세스를 시작하고 stdin/stdout으로 로컬 메시지를 교환했다. 공식 CLI가 기존 계정으로 서비스와 통신한다. 앱은 모델 API, SDK, API 키를 사용하지 않는다. 재현 스크립트는 깨끗한 자식 환경을 구성하고 테스트 폴더를 매 실행 새로 생성한다. [Codex App Server 공식 문서](https://learn.chatgpt.com/docs/app-server)

| 검증           | 관찰한 결과                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 문서 생성      | `codex exec`가 Markdown 파일을 생성했다. 이어진 app-server 시험에서도 Codex가 생성한 초안과 수정본을 각각 저장하고 다시 읽어 가상 자료의 필수 사실과 파일 해시를 확인했다. 초안은 그대로 보존됐다.                             |
| 업무 검토 승인 | 검증 스크립트의 승인 조건으로 확인했다. 대기와 거절 시 다음 작업은 0회였고, 허용 후 초안 내용을 입력으로 사용한 수정 실행은 1회였다. 브라우저 승인과 영속 기록은 T02·T03 범위다.                                               |
| CLI 도구 승인  | 실제 명령 승인 요청을 받았다. 승인 전 마커 파일은 없었고, `decline`에는 `declined` 상태와 파일 미생성, `accept`에는 `completed` 상태와 파일 생성이 일치했다. 결정은 테스트 마커 명령과 경로가 일치할 때만 스크립트에서 보냈다. |
| 중단           | 승인된 45초 대기 명령이 Codex의 하위 프로세스로 실행 중인 것을 확인한 뒤 `turn/interrupt`를 보냈다. `interrupted`를 받았고 CLI는 종료 코드 0으로 닫혔다. 별도 PID 검사에서 두 프로세스가 사라진 것을 확인했다.                 |

[초안](../../docs/t01/codex/draft.md), [수정본](../../docs/t01/codex/revised.md), [선별한 이벤트 기록](../../docs/t01/codex/evidence.jsonl), [재현 스크립트](../../scripts/verify-t01-codex.mjs). 이벤트 기록은 검증 항목과 상태·해시만 남기고 원시 stdout, 계정 정보, 대화 ID를 제외했다.

프로젝트 루트에서 설치된 Codex와 기존 ChatGPT 로그인으로 실행한다. 검증에만 사용하는 명령이며 앱 시작이나 자동 테스트에 연결되어 있지 않다.

```sh
nvm use
node scripts/verify-t01-codex.mjs "$(command -v codex)"
```

첫 중단 시도는 실행 중인 명령을 관측하지 못해 미확인으로 남겼다. 재시험에서는 명령 승인 후 하위 PID를 관측해 확인했다. 자동화 환경의 기본 샌드박스는 Codex 상태 저장소 초기화를 막아 실제 실행과 PID 검사에는 작업 샌드박스 밖 실행이 필요했다. 브라우저 연결, Codex 로그인 만료·사용 한도, 종료 실패 후 복구는 미검증이다. 중단 전에 이미 발생한 행동의 취소는 보장하지 않는다.
