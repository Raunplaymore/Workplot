# T02 작업 정의와 실행 기록 저장

작업 흐름은 SQLite에 전체 정의를 버전별로 저장한다. 데이터베이스는 기존 버전 1에서 버전 2로 트랜잭션 안에서 변경되며 기존 설정을 보존한다. 노드의 화면 좌표와 실행 순서는 독립적이다. 실행 순서는 연결의 방향으로 결정되며, 한 흐름은 순환 없는 직렬 단계만 허용한다.

흐름을 만들면 버전 1을 받는다. 수정 요청은 열어 본 버전 번호를 포함한다. 저장할 때 최신 버전이 이미 바뀌었으면 충돌을 반환한다. 정상 저장은 새 버전을 추가하고 기존 정의를 보존한다. 업무 목표·완료 기준·단계별 전달 문서도 같은 버전에 저장한다. 기존 정의에서 전달 문서 선택이 없으면 직전 작업 결과를 사용한다. 선택을 지정한 경우 앞서 실행되는 작업의 문서만 최대 4개까지 연결할 수 있다.

## 로컬 브라우저 연결

| 요청                                       | 결과                                                                                                |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `POST /api/session`                        | 같은 출처의 브라우저에서 `X-Studio-Client: browser`를 보내면 현재 서버 수명의 세션 쿠키를 발급한다. |
| `GET /api/workflows`                       | 각 흐름의 최신 버전과 이름을 가져온다.                                                              |
| `POST /api/workflows`                      | 작업 정의를 받아 새 흐름의 버전 1을 만든다.                                                         |
| `GET /api/workflows/:id`                   | 흐름의 최신 버전과 전체 정의를 가져온다.                                                            |
| `GET /api/workflows/:id/versions/:version` | 특정 버전의 전체 정의를 가져온다.                                                                   |
| `PUT /api/workflows/:id`                   | `{ baseVersion, definition }`을 받아 다음 버전을 저장한다. 오래된 기준 버전에는 409를 반환한다.     |
| `GET /api/runs/:id`                        | 저장 당시의 실행 상태, 고정한 흐름 버전, 도구 버전만 브라우저에 반환한다.                           |

세션은 단일 사용자 로컬 작업실 전용이다. 쿠키는 HttpOnly·SameSite=Strict이고 서버 재시작 후에는 새로 받아야 한다. 허용 Host는 빌드 화면의 `127.0.0.1:4310`과 개발 화면의 `127.0.0.1:5173`, `localhost:5173`이다. 쓰기와 세션 발급에는 같은 출처의 Origin이 필요하다. 모델 API·SDK·계정 키를 사용하지 않는다.

## 실행 기록

서버 저장 함수는 존재하는 작업 버전에 실행을 연결한다. 저장하는 CLI 정보는 Codex 버전, 세션 식별자와 앱이 시작한 프로세스의 소유 식별자·PID다. 로그와 결과는 실행별 폴더의 상대 참조로 만든다. 결과 참조는 제한된 Markdown 파일명만 허용한다. 브라우저에는 세션·PID·파일 경로를 반환하지 않는다. 이 단계의 파일 참조는 실제 파일을 열거나 파일의 존재를 판정하지 않는다.

실행 기록의 생성은 서버 내부에서만 사용한다. 실제 CLI 실행·상태 갱신과 브라우저 편집 화면 연결은 [1차 개발 검증](../../docs/phase-1/verification.md)에 기록했다.

## 검증

`npm test`는 초기 v1 설정 보존, 새 프로세스의 버전·실행 기록 복원, 재시작 후 이전 세션 무효화, 동시 저장 충돌, 잘못된 연결·파일명·요청 출처 거절, SQLite 쓰기 실패 후 기존 데이터 보존을 검증한다. 실제 CLI 실행과 파일 검증은 이 과제의 저장 테스트에 포함되지 않는다.

Chromium 확인에서는 Vite 개발 프록시를 임시 SQLite 서버에 연결했다. 세션 없이 목록 요청 401, 세션 발급 204, 작업 저장 201, 페이지 새로고침 뒤 동일한 작업 정의를 200으로 읽었다. 기존 4310 서버와 작업 데이터베이스는 이 검사에 사용하지 않았다.
