# Codex Agent Crews Project Config

> 사용자 확정 방향: 앱은 모델 API 직접 호출·API 키 설정·SDK 기반 실행을 사용하지 않는다. 기존 Claude Code·Codex 도구 연결은 허용된 제품 방향이다. 공식 로그인·권한 경로를 사용하고 숨긴 키·프록시로 API 방식에 우회 연결하지 않는다. 도구 내부 서비스 통신은 완전 오프라인과 구분한다. API 도입은 사용자의 별도 명시 요청 전까지 절대 금지한다.

`codex-harness`로 작성한 프로젝트 전용 지침이다. 자동 설치 스크립트가 생성한 파일이나 실행 가능한 에이전트 설정이 아니다.

## Project Meta

- Response language: ko
- Commit convention: 미정, 기존 규칙이 생기면 따른다.
- Branch convention: 미정, 기존 작업을 보존한다.
- Issue tracker: 미설정, 과제 ID T01–T10을 사용한다.

## Custom Rules

- [stack-profile.md](stack-profile.md)의 실제 경로와 설치된 라이브러리를 우선한다.
- [task-verification.md](task-verification.md)의 해당 과제 목표·판정 기준을 구현과 검토에 사용한다.
- 제품 MVP는 단일 사용자·한 실행 제공자·직렬 흐름이다. Electron, 내장 터미널, 병렬·분기·반복 실행, 임의 플러그인 설치는 후속 범위다.
- Claude Agent SDK는 사용 중단한 과거 의존성이다. 기존 Claude Code·Codex CLI 중 검증된 도구 하나부터 연결한다. 설치·import 성공을 인증·실행·승인·중단 지원의 증거로 대신하지 않는다.
- 작업 노드와 담당자를 구분한다. 담당 도구와 실행 단계를 각각 표시한다.
- 상태 변경 API를 추가할 때 로컬 세션 인증과 Host/Origin 검사를 함께 구현한다. 루프백 바인딩만으로 접근 제어가 완성됐다고 보지 않는다.
- 파일·도구 접근은 실행 경계에서 검사한다. cwd 지정이나 프롬프트만으로 파일 접근이 제한됐다고 주장하지 않는다.
- 실행·승인은 구체적 입력·행동·대상·버전에 연결한다. 입력이나 행동이 바뀌면 필요한 승인을 다시 받는다.
- 중단 후 새로운 단계·도구 호출을 막는다. 이미 발생한 외부 행동이 취소됐다고 표시하지 않으며 종료 미확인은 상태 불명으로 남긴다.
- 재접속이나 프로세스 재시작을 이유로 확인되지 않은 행동을 자동 재실행하지 않는다.
- 실제 API 키·사용자 자료를 테스트 fixture에 넣지 않는다. 기존 도구 실행 검증은 공식 로그인·권한 경로와 현재 요청 범위를 따른다. 앱에서 모델 API를 직접 호출하지 않는다.

## Verification Options

- Type check: **on**, TypeScript 변경 시 `npm run typecheck`.
- Lint: **on**, 코드 변경 시 `npm run lint`.
- Test: **auto**, 변경된 동작과 중요한 실패 경로를 검증한다.
- 웹·서버 통합 변경: 관련 Vitest/Playwright 검사와 `npm run build`.
- 문서 변경: 실제 파일·링크·명령 확인과 해당 문서의 Prettier 검사.
- 실행 명령과 포트 주의사항은 [stack-profile.md](stack-profile.md)를 따른다.

## Orchestration

- Lead role: **off**
- 기본은 한 에이전트가 분석 → 구현 → 검증을 수행한다.
- 아래 역할은 책임 구분이며 별도 프로세스나 모델을 자동 생성하는 설정이 아니다. 별도 에이전트 작업은 현재 요청과 적용 지침이 허용하는 경우에만 사용한다.

| 역할           | 책임                                                         | 전달할 결과                            |
| -------------- | ------------------------------------------------------------ | -------------------------------------- |
| planner        | 해당 과제, 선행 조건, 관찰 가능한 기대 결과와 변경 범위 확정 | 대상 경로, 완료 기준, 검증 사례        |
| component-dev  | 와이어 편집기·대시보드·접근성, T04–T06 중심                  | UI 변경, 서버 계약 연결, 브라우저 검증 |
| api-integrator | 제공자·공통 계약·저장·실행·복구, T01–T03·T07–T09 중심        | 서버 변경, 입력 검증, 실행·파일 증거   |
| reviewer       | 코드와 실제 결과를 기준으로 해당 과제 판정, T10 통합 확인    | 통과·실패·미검증, 회귀와 남은 제약     |

## 결과 보고

변경한 동작, 검증한 조건, 증거 위치, 남은 한계를 보고한다. 실행하지 않은 검사를 통과로 표시하지 않는다. 측정하지 못한 비용·사용량은 미측정으로 둔다. 테스트 통과를 배포 또는 공개 승인으로 해석하지 않는다.
