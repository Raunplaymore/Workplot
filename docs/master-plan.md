# Workplot 마스터 계획

2026-11-19 기준. 1차 목표였던 **브라우저에서 작업 흐름 편집 → 실제 Codex로 초안 생성 → 사용자 검토 → 수정본 확인**은 로컬 환경에서 검증했다. T05에서는 **짧은 목표로 새 흐름을 설계하고 기존 흐름을 수정하는 경로**를 실제 Codex와 브라우저에서 검증했다.

## 다음 개발 순서

| 순위    | 개발 범위                                                                                                                 | 다음 단계로 넘어가는 기준                                                                                                                        |
| ------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 · T05 | **설계 확인 질문 검증.** 미지원 도구가 필요할 때의 안내를 확인한다.                                                       | 실제 CLI가 확인 질문을 반환하고, 사용자가 요청을 보완하기 전까지 편집·저장·업무 실행이 발생하지 않는지 검사한다.                                 |
| 2 · T07 | **완료한 작업의 중간 단계부터 새 실행.** 변경한 지침을 시험할 때 유효한 선행 결과를 입력으로 재사용한다.                  | 초안 호출은 0회, 변경 단계와 필요한 후속 단계만 새 실행에 기록한다. 이전 실행 파일의 해시는 유지되고 변경 결과는 필요한 승인을 다시 받아야 한다. |
| 3 · T09 | **원안과 수정안 비교.** 같은 자료와 평가 기준에서 한 가지 변경이 만든 차이를 보여준다.                                    | 영업시간이 있는 자료·없는 자료·서로 충돌하는 자료에서 근거와 결과를 대조한다. 판단이 어려운 경우를 표시하고 사용자가 선택한 변경만 적용한다.     |
| 4 · T10 | **첫 사용자 시작과 재사용 검증.** T05 시안부터 어느 단계에서 설명이 필요한지 관찰하고, 통합 검증은 T07·T09 이후 진행한다. | 준비되지 않은 환경에서 시작부터 결과 재사용까지 독립 완료 여부, 걸린 시간, 도움이나 터미널이 필요했던 지점을 기록한다.                           |

T06·T08은 변경과 연결된 회귀 검증을 계속한다. 예를 들어 T07에서 새 실행을 도입할 때 두 실행 사이를 전환하거나 서버를 재시작해도 문서·승인 대상이 뒤섞이지 않는지 확인한다. 모델 실행은 기존 도구의 공식 로그인 경로를 사용한다.

### T05 목표에서 새 흐름 생성

“매장 소개 초안을 쓰고 내 승인을 받은 뒤 수정본을 만들어줘”를 실제 Codex로 설계했다. 사용자 승인이 초안과 수정본 사이에 있고 수정본 입력은 초안이다. QA에서 취소·적용 직후 저장된 흐름은 2개였고, 별도 저장 후 새 ID의 v1이 생겨 3개가 됐다. 설계용 CLI는 두 번 호출했고 업무 호출·실행·결과 폴더 증가는 모두 0건이었다. 서버·계약 22건, 브라우저 4건, 실제 Codex 시나리오 28건이 통과했다. ### T05 설계 확인 질문과 답변

“매장 일을 도와줘”에 실제 Codex가 필요한 문서 종류를 물었다. 답변을 입력하고 전송하기 전까지 와이어를 표시하지 않았고 흐름은 기존 3개였다. “매장 소개 초안을 쓰고 승인 뒤 수정해줘”를 전송한 후 초안 작성 → 사용자 승인 → 수정본 작성 와이어와 초안 전달 연결을 확인했다. 질문과 답변 후 제안에 각 1회의 설계 호출이 있었고 두 시점 모두 저장·업무 호출·신규 실행은 0건이었다.
