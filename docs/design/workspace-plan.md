# 워크플로 스튜디오 전체 화면 작업공간 설계안

[조작 가능한 HTML 시안](workspace-preview.html) · 브라우저에서 파일을 열면 된다. 노드를 선택해 지침을 바꾸거나, **실행 현황 → 실행 열기 → 검토할 문서 열기**로 이동해 승인과 거절을 시험할 수 있다. 설계 변경과 결정은 시안을 열어 둔 동안만 유지된다. 새로고침하면 같은 예시를 다시 검토할 수 있다.

## 사용자가 돌아오는 자리

설계자는 “이 단계는 무엇을 받아 누구에게 넘기는가?”를 보고, 검토자는 “지금 내가 읽고 결정할 문서는 무엇인가?”를 본다. 두 사람이 같은 흐름을 보더라도 필요한 첫 화면이 다르다. 일반 진입점은 **실행 현황**으로 두고, 저장한 흐름이나 특정 실행을 직접 열면 해당 작업부터 보여준다. 시안의 시작 화면은 편집 면적을 먼저 평가할 수 있는 **흐름 설계**다.

현재 앱은 최대 너비 1320px, 바깥 여백 36px인 본문에 실행 현황, 편집기, 실행과 결과, 도구 상태가 차례로 놓인다. 현황에서 편집기로 가는 동작은 페이지 안 링크다. 목표는 브라우저 탭 전체에 하나의 작업공간을 유지하고, 가운데 작업면을 바꿔 쓰는 것이다.

| 자리          | 기본 화면과 조작                                                              | 선택했을 때                                                                                                                                                   |
| ------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 왼쪽 탐색     | 항상 같은 위치에 **실행 현황**, **흐름 설계** 두 항목을 둔다.                 | 현황은 검토 대기와 최근 실행, 설계는 마지막으로 열었던 흐름과 선택한 단계를 복원한다.                                                                         |
| 상단 바       | 흐름 이름, 저장 버전, 저장 여부를 둔다. 이름을 눌러 흐름 목록·새 흐름을 연다. | 설계에서는 저장·실행, 실행 상세에서는 실행 ID·고정 버전·가능한 중단 동작을 보여준다. 저장 전 변경 사항이 있으면 실행 버튼 옆에서 이유와 저장 동작을 제공한다. |
| 가운데 작업면 | 설계는 연결도, 현황은 실행 표, 검토는 문서 본문에 면적을 준다.                | 선택한 단계·실행·문서가 바뀔 때 같은 화면 안에서 내용을 교체한다.                                                                                             |
| 오른쪽 패널   | 선택한 대상의 속성과 가능한 다음 행동만 둔다.                                 | 단계 선택 시 담당·입력·지침·결과, 빈 캔버스 선택 시 흐름 목표·입력 자료·완료 기준을 연다. 검토 때는 문서와 결정 버튼을 함께 볼 수 있다.                       |
| 상태·로그     | 하단 한 줄에 로컬 연결 상태를 둔다. 도구 상태는 여기서 열어 본다.             | 실행의 최근 이벤트는 상세에 표시하고 전체 로그는 펼쳐서 본다. 긴 로그와 문서는 각각 스크롤한다.                                                               |

## 대표 동선

1. **흐름을 설계한다.** 처음에는 ‘초안 작성 → 사용자 검토 → 수정본 작성’ 예시를 연다. 각 노드에는 담당, 작업명, 넘길 파일 또는 결정이 보인다. 노드 선택 시 오른쪽에서 지침을 수정한다. 연결선은 실행 순서를, 노드의 ‘받는 문서’는 실제 문서 출처를 뜻한다. 두 정보는 따로 표시한다.
2. **흐름을 바꾼다.** 선택한 단계 뒤에 작업·AI 검토·사용자 검토를 삽입한다. 포트를 연결하거나 키보드로 ‘다음 단계’를 선택할 수 있다. 순서·연결·입력 변경 시 업무 설계서의 실행 순서와 문서 전달표를 갱신한다. 끊긴 선, 순환, 뒤 단계의 결과를 입력으로 지정한 경우 문제 위치에 안내한다. 저장·실행 가능 여부는 기존 검증 규칙을 따른다.
3. **저장하고 실행한다.** 저장 성공 후 버전을 표시한다. 실행 상세에서 그 버전의 흐름과 현재 단계를 함께 본다. 설계를 고쳐도 이미 시작한 실행의 지침과 버전은 유지한다. 현황으로 돌아갔다가 실행을 다시 열어도 같은 실행을 이어서 본다.
4. **문서를 검토한다.** 대기 행을 열면 파일명, 작성 단계, 검토 요청이 보인다. 문서를 연 뒤에 ‘승인하고 계속’을 활성화한다. 승인하면 수정 단계로 이동하고 거절하면 중단과 보존된 초안을 표시한다. Codex의 추가 질문은 ‘질문에 답하기’로 표시한다.
5. **실패를 처리한다.** 현재 단계, 마지막 이벤트, 생성된 파일을 한 화면에서 확인한다. 서버가 허용한 실패 단계에 재실행을 제공한다. 승인한 초안이 바뀌면 재실행이 차단된 이유를 알려준다. 중복 클릭·두 탭 결정·재접속 후에는 서버가 돌려준 상태와 결과 목록으로 양쪽 화면을 맞춘다.

## 크기와 조작

| 화면 폭     | 배치와 조작                                                                                                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1280px 이상 | 72–88px 탐색, 270–344px 속성 패널, 나머지는 전부 캔버스다. 두 패널을 제외한 공간에 너비 상한을 두지 않는다. 노드 선택은 뷰포트를 이동시키지 않는다. 팬·줌·전체 맞춤은 React Flow 조작을 쓴다. |
| 801–1279px  | 탐색 폭과 패널 폭을 줄인다. 긴 흐름은 캔버스 안에서 이동한다. 속성 패널을 접으면 전체 연결도에 공간을 돌려준다.                                                                               |
| 800px 이하  | 위쪽에 두 목적지, 그 아래에 순서대로 읽는 단계 목록과 선택한 단계 상세를 둔다. 연결과 재정렬에는 드래그 대체 조작을 제공한다. 검토 화면에서는 문서와 결정을 독립적으로 스크롤한다.            |

읽기 영역은 긴 줄을 피하도록 약 70자로 제한한다. 캔버스에서는 텍스트와 아이콘으로 작성·사람 검토를 구분한다. 초록은 선택·주요 행동, 황토색은 대기, 적색은 실패·거절에 사용한다. 상태 이름을 항상 함께 쓴다. 키보드로 탐색 → 단계 → 속성에 진입할 수 있어야 한다. 패널을 닫으면 포커스를 열었던 항목으로 돌려준다.

## 상태별 첫 행동

| 상황                            | 화면에 표시할 내용과 행동                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 저장한 흐름·실행이 없는 첫 방문 | 빈 현황에서 ‘예시 흐름 열기’로 바로 시작한다.                                                                      |
| 조회 중·연결 끊김               | 조회 중에는 건수를 미정으로 둔다. 연결이 끊기면 마지막 조회 상태와 재연결 동작을 표시하고 실행·결정 조작을 잠근다. |
| 중단 요청·종료 상태 미확인      | 요청 처리 중에는 중복 조작을 잠근다. 종료를 확인할 때까지 상태 미확인을 유지하고 최근 이벤트를 연다.               |
| 다른 탭이 먼저 결정함           | 확정된 결정과 현재 단계를 표시하고 만료된 승인 조작을 닫는다.                                                      |
| 저장 충돌·편집 중 화면 이동     | 입력한 지침을 보존한다. 다른 버전이 저장됐음을 표시하고 현재 편집 내용을 확인할 수 있게 한다.                      |

## 적용 순서와 판정 기준

| 순서              | 변경 범위                                                                                                                 | 통과 조건                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1. 공통 틀과 탐색 | App의 너비 제한·여백을 바꾸고 기존 현황·편집기·도구 상태를 새 위치에 배치한다. 화면 전환과 브라우저 뒤로 가기를 연결한다. | 데스크톱에서 주요 동작을 페이지 스크롤 없이 찾고, 화면 왕복 후 선택·입력·캔버스 위치를 보존한다.                 |
| 2. 설계 작업면    | WorkflowStudio의 기존 React Flow, 단계 폼, 저장·검증·되돌리기를 새 배치에 연결한다.                                       | 마우스와 키보드로 단계 추가·재연결·저장·다시 열기가 가능하고, 설계서와 저장 버전의 순서가 일치한다.              |
| 3. 운영과 검토    | 기존 실행 표, 문서 미리보기, 결정·중단·재실행, 로그를 현황과 상세로 옮긴다.                                               | 초안 열기 전 승인 잠금, 승인·거절, 중단, 실패 단계 재실행과 두 탭 충돌에서 화면·로그·결과 파일이 일치한다.       |
| 4. 사용성 확인    | 프롬프트 설계가 처음인 사용자에게 예시의 중간 단계 삽입과 검토 대기 처리 과제를 준다.                                     | 별도 설명 없이 문서 출처를 찾고 승인 결과를 예측하는지 관찰한다. 도움을 요청한 지점과 잘못 누른 조작을 기록한다. |

첫 적용은 웹 레이아웃과 화면 전환에 집중한다. 기존 서버의 버전·승인·실행 계약과 로컬 Codex 연결을 그대로 사용한다. HTML 시안의 검증 범위는 화면 배치, 노드 선택, 작업 지침 편집, 검토 문서 열기와 결정이다. 자유 배선·실행 시작·중단·충돌 복구는 실제 앱에 배치한 뒤 [기존 QA 목록](../phase-1/qa.md)으로 판정한다.
