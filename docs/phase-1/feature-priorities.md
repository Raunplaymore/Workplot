## 이번 묶음의 완료 기준

- **15·23·27** 새 자료 입력창을 닫거나 페이지를 새로고침해도 같은 탭·흐름·버전에서 내용을 복원한다. 다른 흐름과 격리하고 누락 필드명과 실제 전송 자료를 확인할 수 있다. 실패하면 입력을 보존하고 접수 성공 또는 직접 지우기 후 정리한다.
- **48** 삭제 전 새 연결과 명시적 자료 참조의 영향을 확인할 수 있다. 영향 확인만으로 편집·저장·실행 상태가 바뀌지 않는다. 삭제한 뒤 되돌리면 단계와 연결이 복원된다.

## 개발 결과 · 2026년 11월 22일

1·15·23·27·48에 이어 3·22·46을 반영했다. 남은 후보는 42건이다. 실행 상세의 와이어 비교는 시작 당시의 순서·입력과 최신 저장본을 보여준다. 새 저장 버전이 있으면 과거 버전에서 단계 지침을 바꾸는 재실행은 차단한다. 최신 버전의 완료 실행에서는 재사용할 문서와 다시 수행할 범위를 먼저 확인한다.

격리 QA에서 실제 Codex v1 실행의 승인 대기 중 확인 메모 단계를 추가해 v2를 저장했다. v1 수정본은 초안을, v2 수정본은 확인 메모를 입력으로 받았다. 두 파일의 SHA-256을 각 Codex 호출 기록과 대조했다. 구버전 재실행은 409였고, v2 수정 단계의 재실행은 v3로 시작해 초안·메모를 원본 그대로 재사용했다. 승인을 새로 받은 후 수정 단계만 한 번 호출됐다. Chromium 1440px·390px에서 비교와 차단을 확인했다. 비교 캡처는 개발 실행 b44e60f9-1f95-443f-a150-a2120ebd264a의 compare-1440.png와 compare-390.png다.

### 실행 접수와 검토 결정 · 후보 12·26·43

개발 실행 151b6406-64bd-4a89-a6d1-762a30f282c1에서 접수 중 표시를 구현하고 로컬 앱에 반영했다. 서버는 검토 결정과 대상 단계·게이트를 실행 기록에 보존한다. 늦게 도착해 거절된 결정 요청은 해당 실행을 다시 읽고, 실행 상세에는 서버가 수락한 최근 검토 결과가 표시된다. 이전 버전의 기록에 결정 정보가 없으면 값을 추정하지 않는다.

실제 Codex QA Q01·Q02·Q06~Q10을 통과했다. 거절 우선이면 두 탭 모두 거절로 표시되고 초안만 남았으며, 승인 우선이면 두 탭 모두 승인으로 표시되고 수정본이 하나 남았다. 격리 서버 재시작 후 두 결과를 다시 열어 확인했다. 실행 접수 후 응답만 유실한 실험에서는 재전송 시 동일한 실행 ID, 실행 1건, 초안 호출 1회를 확인했다. 상세 근거는 개발 실행 폴더의 receipt-qa.json에 있다.
