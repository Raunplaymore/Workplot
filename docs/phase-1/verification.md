# 1차 개발 T03–T04 검증

T01에서 확인한 기존 Codex CLI와 T02의 SQLite 작업 정의를 브라우저 편집기와 연결했다. 개발 화면에서 매장 소개 흐름을 불러와 자료·지침·담당 도구·작업 스킬을 편집한다. 위·아래 순서 변경 버튼으로 실행 순서를 바꾸고 노드 드래그로 화면 배치를 바꾼다. 저장하면 버전이 만들어지고 실행은 그 버전을 참조한다.

## 실행 경계

- 로컬 서버는 터미널에서 확인 가능한 기존 Codex ChatGPT 로그인을 사용한다. 모델 API, 키, SDK 없이 CLI를 별도 프로세스로 시작한다.
- 시험한 범위는 직렬 문서 작성이다. Codex는 임시 폴더에서 읽기 전용으로 시작한다. 명령 실행·웹 검색·플러그인·MCP는 연결하지 않으며, 문서나 확인 질문만 결과로 받는다. Claude Code 실행과 외부 스킬 설치는 이 화면에서 제공하지 않는다. 자료 사실 확인 스킬은 앱에서 제공하는 지침이다.
- 서버는 초안 내용을 다음 단계 입력으로 전달한다. 승인 요청은 실행 ID와 일회성 검토 지점으로 구분한다. 사용자가 확인 질문에 답하면 답변을 해당 단계에만 전달한다. 변경한 버전은 별도로 저장되며 진행 중인 실행은 고정된 버전을 유지한다.
- 실행별 폴더에 문서와 상태 이벤트를 저장한다. 결과 파일은 서버가 정한 이름으로만 읽고 브라우저에는 일반 텍스트로 전달한다. 완료 전에 결과를 다시 읽어 검증한다. 앱이 시작한 CLI의 종료를 확인할 수 없으면 상태를 미확인으로 표시한다.
- 개발 화면과 빌드 화면은 기존 T02 세션을 사용한다. 실행 시작, 승인, 중단도 같은 세션·출처 검사 뒤에 처리한다.

## T01–T04 보강

- **T01:** 실제 경로는 기존 Codex CLI다. 미사용 Claude Agent SDK 의존성과 SDK 전용 시험 코드를 제거했다.
- **T02:** 업무 목표, 완료 기준, 단계별 전달 문서를 작업 정의와 같은 버전에 저장한다. 저장 시 자기 자신·뒤쪽 단계·사용자 검토·삭제된 노드·중복 입력 참조를 거절한다. 예전 저장 정의는 직전 작업 결과 전달 동작을 유지한다.
- **T03:** 저장 버전에서 파생한 업무 설계서와 선택한 문서만 해당 단계에 전달한다. 각 문서는 다음 호출 직전에 실행 결과와 대조한다. 완료 기준은 작성 지침이며 자동 품질 판정이나 경로 전환을 뜻하지 않는다.
- **T04:** 선택한 노드 뒤에 일반 작업, AI 검토, 사용자 검토를 삽입할 수 있다. 업무 설계서에는 단계 순서와 결과 전달이 반영된다. 연결이 깨지면 저장 시 해당 단계가 선택되고 연결을 고칠 수 있다.

보강 검사에서 타입·린트·빌드, 현행 Vitest 17개, Chromium 16개가 통과했다. Chromium은 AI 검토 삽입과 연결 변경, 잘못된 연결의 저장 거절, 되돌리기, 버전 재열기, 승인 뒤 초안과 검토 의견이 함께 전달되는 것을 확인했다. 서버 시험은 승인 대기 중에 선택된 이전 초안의 내용이 달라지면 후속 실행을 차단하는 것을 확인했다.

별도 실제 CLI 시험에서는 가상 흐름을 로컬 서버로 저장하고 Codex 0.166.0으로 실행했다. 초안과 AI 검토 의견만 있는 상태에서 사용자 승인을 기다렸고, 승인 후 수정본에 두 문서에 각각만 들어 있던 표식과 설계서의 완료 기준에만 있던 표식이 모두 포함됐다. [실제 CLI 시험 기록](workflow-guide-evidence.json)
