# 워크플로 QA 목록

브라우저와 로컬 서버의 편집·설계·실행 흐름을 검증한다. Q01–Q26은 가상 서점의 고정 v1 정의를 사용한다. Q27은 편집기 기본 예제를 별도 흐름으로 저장한 뒤 실제 Codex로 변경안을 생성한다.

| 영역             | 검증 기준                                                                                |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 빌드와 정적 검사 | Node 26에서 타입 검사, ESLint, Prettier, 전체 빌드 통과                                  |
| 로컬 도구와 저장 | CLI 설치와 로그인 상태 구분, 중복 감지 요청, SQLite 버전 보존과 쓰기 실패 처리           |
| 실행 경계        | 세션·Origin·Host 검사, 결과 파일 경계, 잘못된 노드·문서 연결 차단                        |
| 워크플로 편집    | 키보드와 마우스 와이어 변경, 되돌리기, 설계서 갱신, 버전 저장·재열기, 저장 순서대로 실행 |

Node 26과 로그인된 Codex CLI, 설치된 Playwright Chromium으로 프로젝트 루트에서 `npm run qa`를 실행한다. QA 서버는 127.0.0.1:5173을 사용한다. 코덱스 사례는 한 번에 하나씩 실행하며 기존 CLI 계정의 사용량이 발생한다. 실행 요약은 콘솔에 표시된 `report.md`에서 확인한다. 실행마다 생성되는 `.local/qa-*/`에 검사 결과, 브라우저 보고서, 실제 CLI 호출·PID, 사례별 판정 근거와 원본 문서를 보관한다.

Q14–Q16은 사례별 저장소에서 실행한다. 강제 종료 직전의 단계·호출·파일을 기록하고 새 서버 PID, 동일 실행 ID, 재접속과 같은 실행 ID의 시작 요청 이후 호출 수, 파일 해시를 대조한다. 작성 중인 Q14·Q16은 실제 Codex 실행 파일과 PID를 확인한 뒤 서버를 종료한다. 서버를 다시 켜기 전에 2초 이내에 해당 PID와 프로세스 그룹이 모두 사라져야 통과한다. 사례별 JSON에 관측 시간과 전후 파일 해시를 남긴다.

Q17·Q18은 해당 실행의 네이티브 Codex PID에만 SIGKILL을 보낸다. 같은 서버에서 대시보드의 실패 표시와 새로고침 후 상태, 같은 단계의 최종 실패 로그, 추가 CLI 호출 수, 결과 파일 목록과 해시를 대조한다.

Q19·Q20은 실패를 확인한 뒤 대시보드에서 명시적으로 재실행한다. Q19는 검토 대기를 관찰한 뒤 QA 서버를 정상 종료한다. 정상 종료 시에는 승인 대기를 저장하며 Q15는 강제 종료를 검사한다. Q20은 서버 재기동 후 재시도하며 승인 문서와 Codex 입력의 SHA-256을 대조한다.

실행 환경은 단일 사용자·직렬 워크플로와 단일 로컬 서버다. 장시간 부하, 실제 사용자 사용성 평가는 이번 목록의 검증 범위 밖이다.

### Q39 목표에서 기존 흐름 찾기

실제 Codex에 “새 카페 소개문을 만들고 싶어”를 입력한다. 저장된 각 흐름의 최신 버전 메타정보만으로 카페 소개문 흐름 하나와 이유를 제안하는지 검사한다. 추천 중 다른 버전을 저장해도 사용자가 선택한 버전으로 빈 자료 입력창이 열려야 한다. 추천과 선택 전후의 설계 호출, 업무 호출, 저장 및 결과 파일을 대조한다.

### 와이어 편집의 위치와 선택

목표는 사용자가 화면에서 읽는 순서와 실행 순서를 일치시키고, 한 번의 편집 후에도 작업하던 위치에서 계속할 수 있게 하는 것이다.

- 가로 흐름 중간에 단계를 넣으면 필요한 자리만 비운다. 순서 변경은 두 단계의 자리를 맞바꾼다. 삭제 후 이웃 단계를 선택하고 되돌리면 편집 전 선택과 배치가 복구된다.
- 화면 안의 단계는 현재 시점을 유지하고, 밖에 새로 생긴 단계는 배율을 유지한 채 보이는 곳까지 이동한다. 직접 배치한 여러 줄의 흐름에서는 추가할 때 기존 단계 좌표를 유지한다.
- 선의 끝을 옮겨 연결을 교체한다. 빈 곳에 놓거나 순환을 만들면 원래 연결을 보존한다. 좁은 화면에서는 단계 목록과 다음 단계 선택으로 편집한다.
- 브라우저 포인터 및 화면 위치 검사는 `e2e/wire-editing.spec.ts`, 키보드·좁은 화면은 `e2e/workflow.spec.ts`, 실제 Codex 삽입·취소·적용은 Q27에서 확인한다.

정상 업데이트 복구 검사는 같은 인계 링크와 문서 해시, 승인 식별자를 비교한다. 재시작과 두 탭의 재접속 동안 Codex 호출이 추가되지 않고 두 탭이 승인해도 후속 세션은 하나여야 한다. 재시작 사이 파일이 바뀌면 이전 승인을 거부한다.
